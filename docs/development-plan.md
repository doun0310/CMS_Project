# CMS Printer Application Development Plan

기준일: 2026-07-23

## 1. 프로젝트 개요

사내 CMS와 연동되는 승인 기반 프린터 애플리케이션을 구축한다.

목표는 다음과 같다.

- 인쇄 요청의 표준화
- 역할 기반 승인 체계 도입
- 프린터 출력 이력 및 감사 로그 확보
- 재인쇄 및 민감 문서 통제
- 향후 Print Agent 및 관리자 UI 확장 기반 확보

## 2. 현재 진행 상태

현재 저장소에는 다음 초기 구성이 완료되어 있다.

- PostgreSQL DDL 작성
- 초기 시드 데이터 작성
- Node.js + TypeScript + Express 기반 API 골격 구성
- 인쇄 요청 생성 및 재인쇄 요청 흐름 구성
- 승인/반려 처리 흐름 구성
- 출력 작업 큐 적재 및 재시도 흐름 구성
- 에이전트 Poll / 상태 회신 흐름 구성
- 프린터 / 승인 정책 / 템플릿 관리 API 기본 CRUD 구성
- 감사 로그 저장 구조 구성
- 조직 범위 검증 일부 반영

## 3. 개발 목표 범위

MVP 범위는 아래와 같다.

- 인쇄 요청 등록
- 승인/반려 처리
- 재인쇄 요청 처리
- 승인 완료 건 출력 큐 적재
- Print Agent 작업 수신 및 상태 회신
- 프린터 관리
- 승인 정책 관리
- 템플릿 관리
- 감사 로그 저장

MVP 제외 또는 후속 범위는 아래와 같다.

- SSO 연동
- 관리자 프론트엔드 대시보드
- 복잡한 다단계 승인 규칙 엔진
- 고급 템플릿 편집기
- 통계 대시보드
- 다중 지점 자동 분산 출력

## 4. 개발 단계

### Phase 1. 기반 정비

목표:
- 로컬 실행 가능 상태 확보
- DB 연결 및 환경 변수 정리

작업 항목:
- `npm install` 수행
- `npm run typecheck` 수행
- `.env` 작성 및 DB 연결 확인
- `schema.sql`, `seed.sql` 적용
- 공통 에러 처리 정리

완료 기준:
- 서버 기동 성공
- `/health` 응답 확인
- DB 연결 성공

### Phase 2. 핵심 업무 흐름 안정화

목표:
- 인쇄 요청부터 승인, 큐 적재, 상태 회신까지 핵심 흐름 완성

작업 항목:
- 인쇄 요청 유효성 검증 강화
- 승인 시 조직 범위 검증 강화
- 출력 요청 상태 전이 규칙 보강
- 실패 케이스별 메시지 표준화
- Print Agent 상태 처리 예외 보완

완료 기준:
- 요청 생성 → 승인 → 큐 적재 → 출력 상태 반영 흐름 검증
- 반려 및 재시도 흐름 검증

### Phase 3. 인증 및 권한 체계 고도화

목표:
- 현재 `mockAuth`를 실제 인증 구조로 교체

작업 항목:
- JWT 또는 사내 SSO 방식 확정
- 인증 미들웨어 구현
- 사용자/조직 조회 연동
- 역할 기반 접근 제어 보완
- 감사 로그에 사용자 주체 정확히 반영

완료 기준:
- 실제 로그인 주체 기준 API 권한 제어 가능

### Phase 4. 관리자 운영 기능 보강

목표:
- 운영자가 실사용 가능한 관리 기능 정리

작업 항목:
- 목록 조회 필터링
- 페이지네이션
- 프린터별 조직 매핑 관리 API
- 감사 로그 조회 API
- 문서 유형별 정책 예외 처리

완료 기준:
- 관리자 기능만으로 프린터/정책/템플릿 운영 가능

### Phase 5. 품질 및 배포 준비

목표:
- 운영 투입 가능한 최소 품질 확보

작업 항목:
- 서비스/리포지토리 단위 테스트 추가
- 주요 API 통합 테스트 추가
- 배포 환경 변수 문서화
- 운영 로그 정책 정리
- 장애 대응 절차 정리

완료 기준:
- 핵심 API 테스트 확보
- 배포 절차 문서화 완료

### 백엔드

- DB 스키마 관리
- API 구현
- 승인/출력 비즈니스 로직 구현
- 감사 로그 구현

### 프론트엔드

- 관리자 화면
- 승인 대기 목록 UI
- 요청 등록/이력 조회 UI

### 인프라/운영

- PostgreSQL 운영 환경 구성
- 환경 변수 및 배포 구성
- 로그 및 모니터링 체계 구성

## 7. 주요 리스크

- 프린터 종류별 동작 차이
- 실제 Agent 통신 환경 미확정
- 인증 방식 미확정
- 조직 구조가 단순 1단계가 아닐 수 있음
- 승인 정책이 운영 중 빠르게 복잡해질 가능성

대응 방향:

- Agent 통신 계약을 먼저 고정
- 인증 방식은 조기에 확정
- 조직/정책 로직은 하드코딩보다 확장 가능한 구조 유지
